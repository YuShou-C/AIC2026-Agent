# 选题调研 · 2026-08-31

> 背景：用户否决"代码审查助手"（论证：平台智能体 = 对话框+知识库+工作流，无法接 IDE/仓库；开发者工具战场已被 Claude Code/Copilot 占据，单段粘贴审查是伪需求）。该质疑成立，本调研据"好需求 × 数据不难 × 平台形态契合 × 答辩好讲"重选场景。

## 选需求的第一标准（本次调研沉淀的方法论）

**答案的价值必须主要来自"整理过的权威知识"，而不是"对代码/文件的实时计算"。**
——这样知识库才是护城河，且能回答总决赛必问题："这跟直接问大模型有什么区别？"

## 市场层面发现

1. **RAG 知识库问答是最成熟形态**，行业共识成败在知识库文档质量与切片加工；RAG 最大痛点 = 复杂文档解析与切片质量（恰好对应比赛"数据准备 10 分 + 知识库完成度 20 分"）。
2. 高价值场景集中：智能客服、政策/制度问答（HR、政务、税）、IT 服务台、法律检索、垂直文档生成（Coze 案例库"智能标书通"内置招投标法等 15 个垂直知识库）。
3. **财税咨询 = 智能体渗透最快场景之一**：代账 AI 客服（发票/社保/申报期限咨询）、税局 AI 坐席（深圳"深税 AI 助手"等）、用友/金蝶/慧算账全线布局。行业痛点原文："小规模与一般纳税人政策差异处理、跨区域申报适配、AI 结果需人工复核兜底"——知识库锚定权威政策正是解法。
4. 开发者工具类（代码审查/生成）应避开：通用大模型已充分覆盖，知识壁垒趋零。

## 数据源验证（按候选场景）

| 候选 | 数据源 | 收集难度 | 判断对错的门槛 |
|---|---|---|---|
| **财税办税问答**（商科·财会） | 12366 纳税服务平台公开热点问答（现成 QA 库）+ 结构化办税指南（条件/材料/流程/时限）+ 增值税/个税/企业所得税政策文件 | ★ 最低（公开、海量、QA-ready；人工摘录整理即可） | 低：对照自整政策文件即可核验 |
| Java 升级迁移顾问（工科·软件） | OpenJDK 迁移指南、release notes、社区踩坑文 | 中（多英文、需翻译重构） | 中（需 Java 深度） |
| 病虫害防治问答（农科） | 植保手册、农技推广资料 | 偏高（散、PDF 质量参差） | 高（需植保常识） |
| 代码审查助手（工科） | 编码规范等公开文档 | 低 | 低 | ✗ 需求不成立，弃 |

## 倾向性结论（待用户拍板）

**推荐：财税办税问答助手（AI+商科·财会）**——首发范围控制：面向小微企业主/新任会计的高频问题（增值税申报、发票开具与红冲、小规模纳税人优惠），工作流 = 意图分类 → 政策检索 → 输出"办理流程 + 材料清单 + 政策依据 + 风险提示"。
复赛评分不区分方向，切换无成本；总决赛答辩商业叙事成熟（代账 SaaS、中小企业服务）。

风险与对策：政策有时效性 → 备赛期制作"当前有效"切片并在每条知识标注依据文件与发文时间，答辩时作为"幻觉控制机制"亮点讲。
