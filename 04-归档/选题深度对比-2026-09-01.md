# 选题深度对比 · 2026-09-01

> 任务来源：用户指令"再做几轮深入调研，到底什么样的选题比较适合，这个选题对我专业背景有无要求，数据获取的难度如何，获奖的切入点和领跑点，都分析清楚。在我提供的这几个指标里面，做比较选择。"
> 本文档在 `选题调研-2026-08-31.md`（市场面调研）基础上，补两轮定向检索后做的**多指标对比决策**。

## 0. 调研环境说明（先说诚实的话）

两轮共 11 次检索中，第二轮大部分查询返回"模型知识型回答"甚至伪造 URL（example.com），仅医疗监管部分与第一轮市场面来源（36kr / Coze / CSDN / 腾讯云等，见 08-31 调研文件）可信。因此：

- 本文的**决策依据不依赖这些存疑检索结果**，只依赖三类硬事实：① 复赛/总决赛评分表（规程原文）；② 平台形态（对话框+知识库+工作流，介绍视频确认）；③ 各领域公开数据源的存在性与结构（属可人工核验的公开常识）。
- 检索得到的方向性信息一律标注，待核验项集中在文末第 9 节。
- **这不影响选题结论**：选题的成败变量（评分匹配、数据可得、平台契合）都已掌握。

## 1. "什么样的选题适合"——五条判定规则（第一个问题的答案）

从评分表和平台形态倒推，适合本比赛的选题必须同时满足：

| # | 规则 | 对应的得分/失分 |
|---|---|---|
| 1 | **知识密集**：答案价值来自"整理过的权威知识"，不是实时计算 | 决定知识库 20 分是否是真护城河；决定"和直接问大模型有什么区别"能否答满分 |
| 2 | **数据 QA-ready 且公开**：有现成问答对/结构化条目可摘录 | 决定数据准备 10 分 + 知识库 20 分的弹药量；两周内要能做到 200–400 条 |
| 3 | **用户会自用**：自己就是目标用户，能判断答案对错、能自建测试集 | 决定对话内容质量 10 分的可控性（测试微调环节的底气） |
| 4 | **答辩叙事成熟**：痛点、市场、与裸大模型的差异，三句话讲清 | 复赛需求 5+场景 5 分好写；总决赛"开发制作过程 40 分"好讲 |
| 5 | **可切窄**：首发范围能裁到两三周可完成，且有"时效/依据"类控制故事 | 两周备赛窗口的生死线；也是创新点的来源 |

> 反例：代码审查助手死于规则 1（实时计算、无知识壁垒）；文旅问答死于规则 5（数据时效）+ 平台缺工具调用。

## 2. 评分体系（用户四指标 + 两个必要维度）

每项 1–5 分，越高越好。①② 为用户指定指标（① 反向：要求越低分越高），③④ 为用户指定的"获奖切入点和领跑点"拆成复赛/总决赛两层，⑤⑥ 为决策必需的补充维度。

| 维度 | 衡量什么 |
|---|---|
| ① 专业背景要求 | 不具备该领域背景，能否做出高质量作品、判断答案对错 |
| ② 数据获取难度 | 数据源公开性、结构化程度、QA-ready 程度、两周可加工量 |
| ③ 复赛切入点 | 与复赛 100 分评分表（提示词30/知识库20/架构20/数据10/对话10/需求场景10）的匹配度 |
| ④ 总决赛领跑点 | 答辩差异化：创新叙事、行业验证、"别人没做的角度" |
| ⑤ 平台形态契合 | 对话框+知识库+工作流（无文件系统、无 API 工具调用、无图像）能否承载该场景 |
| ⑥ 两周备赛适配 | 弹药库加工量与 90 分钟 SOP 的可执行性 |

## 3. 候选池与逐项剖析

### A. 财税办税问答助手（AI+商科·财会）★ 现推荐

- **需求成立性**：成立且有行业验证。代账公司 AI 客服、税局 AI 坐席（深圳"深税 AI 助手"）、用友/金蝶/慧算账全线布局（36kr 报告，确证）。行业公认痛点原文："AI 结果需人工复核兜底"——知识库锚定权威口径正是解法。
- **① 背景要求：最低（5/5）**。收集数据 = 摘录 12366 官方口径，不需要会计执业知识；判断答案对错 = 对照政策原文，是"核对"不是"创作"。有财会同学组队更好，没有不影响出品质量。计算机背景反而加分——数据加工、提示词工程本来就是本行。
- **② 数据获取：最容易（5/5）**。三层素材全公开：12366 热点问答（**现成 QA 对**，直接可用）＋ 办税指南（天然结构化：条件/材料/流程/时限）＋ 政策原文。无批量接口需人工摘录，但两周 200–400 条高频 QA 可行。
- **③ 复赛切入点：最顺（5/5）**。需求/场景分析好写（小微企业主/新任会计的具体痛点故事）；知识库可做"QA 对 + 政策条目"双格式显加工深度；工作流 = 意图分类 → 政策检索 → 结构化输出（流程+材料+依据+风险提示），架构 20 分稳；自己能判断对错，对话质量 10 分可控。
- **④ 领跑点（4/5）**：①"权威口径锚定 + 每条答案标注政策依据与发文时间"的幻觉控制机制——直击行业痛点，答辩有现成行业报告佐证；② 市场已验证，商业叙事三句话讲清；③ 对"和大模型直接问有什么区别"有满分答案。扣 1 分原因：财税是热门方向，竞争队伍可能想到同类场景（但"时效标注机制"这个深度多数队伍做不出）。
- **风险与对策**：政策有时效性 → 备赛期做"当前有效"切片 + 依据版本标注（本身就是创新点素材）。

### B. Java 升级迁移顾问（AI+工科·软件）

- **需求成立性**：真实（存量系统升级潮），但开发者遇到问题第一反应是直接问大模型，知识壁垒被通用模型稀释。
- **① 背景要求：高（2/5）**。需要真实 Java 工程经验才能判断答案质量、设计测试集、写出有深度的迁移 QA。没有该背景基本做不出可信作品。
- **② 数据获取：偏难（2/5）**。官方迁移指南/release notes 以英文为主，需翻译重构；中文踩坑资料散落社区、质量参差。
- **③ 复赛切入点（3/5)**：技术深度显专业，但需求/场景故事不如民生场景好讲；对话测试成本高（每条 QA 要懂行才能验证）。
- **④ 领跑点（3/5）**：工科答辩有技术深度加成；但"更聪明的开发问答"故事面对 Claude Code 类工具的天然质疑。
- **⑤⑥**：平台契合中等（3/5，纯文本对话可行）；两周适配差（2/5，英文资料重构 + 专业 QA 制作量大）。

### C. 病虫害防治问答（AI+农科）

- **① 背景要求：高（2/5）**。植保知识可速成常识，但判断"防治方案对不对"需要专业底气，测试集设计难。
- **② 数据获取：偏难（2/5）**。农技推广资料分散、扫描件多、地区性强；QA 对基本要自造，加工量六个候选里最大。
- **③ 复赛切入点（3/5）**：知识库条目可做（症状→诊断→防治），但质量依赖自造素材的密度。
- **④ 领跑点（3/5）**：乡村振兴政策叙事强；**若平台支持图像识别，"拍照识虫"是大亮点——但平台形态未确认多模态能力，赌不得**。
- **⑤⑥**：契合中等（3/5）；两周适配差（2/5）。

### D. 招投标合规问答助手（AI+商科）★ 次推荐

- **需求成立性**：成立，且有形态先例——Coze 官方案例库"智能标书通"内置招投标法等 15 个垂直知识库（确证）。行业里"标书合规自动检查、废标项预警"是真实方向（本轮检索方向性印证，案例细节待核验）。
- **① 背景要求：中（3/5）**。法规条目可摘录；但"什么情况会废标""资格审查怎么过"属评标实务，学生若无商科/法律背景，测试集和答案深度有门槛。
- **② 数据获取：较易（4/5）**。《招标投标法》及实施条例、政府采购法、财政部 87/74 号令等在国家法律法规数据库、财政部官网公开且结构化。扣分点：实务问答素材（真实废标案例、地方细则）散，需切窄。
- **③ 复赛切入点（4/5）**：工作流亮点多（条件核验 → 法条检索 → 材料清单核对 → 风险提示），比 A 的流程更长、更"工程感"；需求故事好（中小企业投标避坑）。
- **④ 领跑点（4/5，双刃）**：先例证明形态可行、答辩好讲；但先例也意味着"别人做过"，创新分要靠差异化角度（如"面向中小企业的废标避坑"而非大而全标书生成）。
- **⑤⑥**：契合好（4/5）；两周适配中（3/5）——法规体量大，首发必须切窄到"政府采购公开招标的废标避坑"这类范围。

### E. 文旅出行问答（AI+商科·旅游）

- **① 背景要求：低（5/5）**——这是它唯一的优势。
- **② 数据获取（3/5）**：景点信息公开，但**票价、开放时间、预约政策高频变动**，知识库一做完就在过期，答辩一问时效就露馅。
- **③ 复赛切入点（3/5）**：问答能做，但无工具调用做不了"实时"。
- **④ 领跑点：最弱（2/5）**。人人都能想到文旅场景，同质化最重；真实行业部署（数字人+多模态+地图/天气/票务 API 联动，本轮检索方向性印证）恰恰是平台做不了的形态——作品天然是行业真实形态的"降级模仿"。
- **⑤ 平台契合差（2/5）**；⑥ 适配中（3/5）。

### F. 健康科普问答（AI+医科·健康）

- **① 背景要求：中（4/5）**。科普级问答可摘录权威指南；但边界把握（科普 vs 医疗建议）需要判断力。
- **② 数据获取（3/5）**：指南/科普库公开量大，但甄别权威来源需要功夫。
- **③ 复赛切入点（3/5）**：能做，但测试集要防"模型给出危险建议"的边界 case，微调成本高。
- **④ 领跑点（3/5）**：合规红线明确且真实——生成式 AI 服务需备案（网信办 2023 暂行办法，确证级常识）、**AI 生成处方被明确禁止**、"场景化管理"监管趋势（本轮检索印证，方向可信）；答辩要花大量力气讲"我们不是诊疗工具"，讲好了是加分、讲不好是致命追问。另：医科方向医学院校参赛者多，撞车概率高。
- **⑤ 契合好（4/5）**；⑥ 适配中（3/5）。

> 快速排除：营销文案/艺术创作类——纯生成、无知识库护城河（规则 1 不满足），知识库 20 分无从体现，六个维度全低，不入矩阵。

## 5. 结论与排序

1. **首选：A 财税办税问答助手**（29/30）。推荐理由三句话：
   - **对专业背景最鲁棒**：在用户背景尚未明确的情况下（见下节），A 是唯一"任何专业都能做出高质量"的候选——数据是摘录官方口径，判断是对照原文，加工是计算机/通用技能。
   - **每一分都有明确打法**：见第 6 节逐分值对应。
   - **领跑点有行业背书**：幻觉控制机制直击"AI 结果需人工复核"的行业公认痛点，有确证来源可引。
2. **次选：D 招投标合规问答**（22/30）。若队伍有商科/法律背景、想要工作流更"工程感"的答辩效果，D 是合理备选；首发范围必须切窄。
3. **不建议**：B/C（背景门槛 + 两周来不及）、E（同质化 + 数据时效）、F（合规追问风险 + 撞车概率）。

## 7. 关于"对我专业背景有无要求"的直接回答

- **A（推荐）**：无硬性背景要求。所需能力 = 文献摘录整理（通用）+ 逻辑判断对错（对照原文）+ 提示词与数据加工（比赛本身要考的）。若有财会/经管背景是锦上添花；纯计算机背景完全成立。
- **D（次选）**：最好有商科/法律相关背景或组到相关队友，否则实务深度（废标情形、资格审查）撑不起来。
- **B/C**：分别硬性要求 Java 工程经验 / 植保专业常识，没有就是硬伤。
- **E/F**：背景要求不高，但分别死于数据时效和合规风险，背景不是主要矛盾。
